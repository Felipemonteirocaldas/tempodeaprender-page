# RULES.md

# Objetivo

Este projeto deve atingir padrão profissional premium de mercado para sites institucionais.

As referências de qualidade são:

- Apple
- Stripe
- Linear
- Notion
- Airbnb
- Vercel

Estas regras possuem prioridade máxima sobre qualquer outra instrução.

---

# Princípios Fundamentais

Toda decisão deve priorizar:

1. Clareza
2. Usabilidade
3. Conversão
4. Performance
5. Acessibilidade
6. Consistência visual
7. Estética

Nunca sacrificar clareza por estética.

Nunca sacrificar performance por efeitos visuais.

---

# Qualidade Visual

Toda interface deve transmitir:

- Profissionalismo
- Credibilidade
- Modernidade
- Clareza
- Consistência

Evitar:

- Visual amador
- Excesso de elementos
- Poluição visual
- Efeitos desnecessários

---

# Mobile First

Toda implementação deve ser desenvolvida considerando mobile primeiro.

Breakpoints mínimos obrigatórios:

- 320px
- 375px
- 768px
- 1024px
- 1366px
- 1920px

É proibido:

- Overflow horizontal
- Elementos cortados
- Conteúdo inacessível

---

# Design System

Todo elemento deve seguir um Design System consistente.

Obrigatório:

- Sistema de cores
- Escala tipográfica
- Escala de espaçamento
- Componentes reutilizáveis

Proibido:

- Valores aleatórios
- Componentes inconsistentes
- Variações sem padrão

---

# Tipografia

Máximo de 2 famílias tipográficas.

Obrigatório:

- H1
- H2
- H3
- Body
- Small Text

Todo texto deve possuir:

- Boa legibilidade
- Contraste adequado
- Hierarquia clara

---

# Espaçamento

Utilizar escala consistente.

Exemplo:

- 4
- 8
- 12
- 16
- 24
- 32
- 48
- 64
- 96

Proibido:

- Espaçamentos arbitrários
- Elementos colados
- Layout apertado

---

# Cores

Utilizar:

- Cor primária
- Cor secundária
- Cor de destaque
- Cores de feedback

Proibido:

- Excesso de cores
- Saturação excessiva
- Contraste insuficiente

---

# Componentes

Todo componente deve ser:

- Reutilizável
- Responsivo
- Acessível
- Consistente

Proibido:

- Código duplicado
- Componentes duplicados
- Variações sem justificativa

---

# Conteúdo

Todo conteúdo deve ser:

- Claro
- Objetivo
- Escaneável

Utilizar:

- Títulos
- Subtítulos
- Listas
- Destaques

Evitar:

- Blocos extensos
- Jargões
- Textos redundantes

---

# CTA

Toda página deve possuir pelo menos um CTA principal.

O CTA deve ser:

- Visível
- Claro
- Relevante

O usuário nunca deve precisar procurar como entrar em contato.

---

# Formulários

Obrigatório:

- Labels
- Estados de erro
- Estados de sucesso
- Feedback visual

Proibido:

- Campos sem contexto
- Erros silenciosos

---

# Acessibilidade

Obrigatório:

WCAG 2.2 AA

Validar:

- Contraste
- Navegação por teclado
- Focus states
- Alt text
- HTML semântico
- ARIA quando necessário

---

# Performance

Metas mínimas:

Performance >= 90

Accessibility >= 95

Best Practices >= 95

SEO >= 95

Objetivo ideal:

100 em todas as categorias.

---

# Core Web Vitals

Metas:

LCP < 2.5s

CLS < 0.1

INP < 200ms

---

# SEO

Toda página deve possuir:

- Title único
- Meta description
- Open Graph
- Estrutura semântica

Obrigatório:

- Sitemap
- Robots.txt

---

# HTML

Priorizar:

- header
- nav
- main
- section
- article
- footer

Evitar divs sem propósito.

---

# CSS

Priorizar:

- Reutilização
- Escalabilidade
- Consistência

Evitar:

- Código duplicado
- Estilos órfãos
- Hacks

---

# JavaScript

Priorizar:

- Simplicidade
- Performance
- Legibilidade

Evitar:

- Complexidade desnecessária
- Dependências sem necessidade

---

# Segurança

Obrigatório:

- HTTPS
- Validação de entradas
- Sanitização
- Proteção contra spam

---

# Processo

Antes de qualquer alteração:

1. Identificar o problema.
2. Entender o impacto.
3. Propor solução.
4. Implementar.
5. Validar.
6. Refatorar se necessário.

---

# Regra Final

Toda alteração deve deixar o projeto melhor do que estava anteriormente.

Se houver dúvida entre duas soluções, escolher a que:

- Simplifica a experiência.
- Reduz a complexidade.
- Aumenta a clareza.
- Melhora a manutenção.
